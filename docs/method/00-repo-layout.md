# 00 — بنية المستودع والتسمية

المستودع مشروع علمي لكتب مترجمة/مُعدّة إلى العربية. البنية أدناه **قارّة**؛ أي كتاب جديد
يأخذ الشكل نفسه حتى تعتمد الأدوات والفحوص عليه.

## الشجرة القانونية

```text
/
├── AGENTS.md              عقد العمل مع المستخدم: بوابة الموافقة وحالة المراجعة
├── README.md              فهرس المستودع: قائمة الكتب وحالاتها
├── CONTRIBUTING.md        دليل المساهم (ملخص تنفيذي يحيل إلى هذا المجلد)
│
├── docs/method/           ← هذا المرجع القار للطريقة والدروس
│
├── assets/                أصول مشتركة بين كل الكتب
│   ├── print.css          التنضيد الافتراضي (RTL، الترقيم، الجداول)
│   └── fonts/             الخطوط المرفقة مع تراخيصها وسجل مصدرها
│
├── sources/               الأصول بلغتها الأم — للقراءة فقط، لا تُعدَّل أبدًا
│   ├── README.md
│   └── <source-slug>/     مثل how-linux-works-2nd-en
│       ├── <OriginalFile>.pdf
│       └── source.json    بيانات الأصل وبصمته وحالته الحقوقية
│
├── books/                 مجلد مشروع مستقل لكل كتاب
│   └── <book-slug>/       مثل how-linux-works-ar
│       ├── README.md      بطاقة المشروع: الحالة، الدفعات، الخطوة التالية
│       ├── manifest.json  الحقيقة الآلية: النطاق، الفصول، الوثائق، الأرشيف
│       ├── ar/            المصادر العربية القابلة للتحرير (تُحرَّر هنا فقط)
│       ├── assets/        اختياري: print.css خاص يتجاوز المشترك
│       ├── coverage/      سجلات مقابلة الفصول بالأصل
│       └── editions/      المخرجات المسلّمة (PDF + Markdown مجمّع)
│
├── scripts/
│   ├── build_book.py      التحقق والبناء لكتاب واحد (--book <slug>)
│   ├── new_book.py        تسجيل أصل جديد وإنشاء مشروع كتاب
│   └── render_pdf.mjs     الترقيم الفعلي عبر Chromium/Paged.js
│
└── tests/                 اختبارات لكل مشروع، بأسماء مسبوقة بـ slug الكتاب
    ├── test_repository_layout.py            فحوص البنية العامة (لكل الكتب)
    ├── test_<slug_snake>_build.py           بناء الكتاب ومخرجاته
    └── test_<slug_snake>_*.py               فحوص خاصة بفصل أو مختبر
```

## قواعد التسمية

| العنصر | القاعدة | مثال |
| --- | --- | --- |
| slug الأصل | `<slug>-<edition>-<lang>` بأحرف لاتينية صغيرة | `how-linux-works-2nd-en` |
| slug الكتاب | `<slug>-<lang>` حيث اللغة هي لغة الهدف | `how-linux-works-ar` |
| ملف الفصل | `NN-<slug-en>.md` بترقيم يطابق الأصل | `02-basic-commands.md` |
| سجل التغطية | `chapter-NN.json` | `chapter-02.json` |
| الدفعة | `<book-slug>-part-NN` | `how-linux-works-ar-part-02` |
| اسم ملف الأصل | يبقى كما صدر، دون تغيير | `HowLinuxWorks.pdf` |

## من يملك ماذا

- **`sources/`** لا يتغير بعد التسجيل. إن تغيّر أصل، فهو أصل **جديد** بـ slug جديد وبصمة
  جديدة، وليس تعديلًا على القديم.
- **`books/<slug>/ar/`** هو المكان الوحيد الذي يُحرَّر فيه النص. `editions/` مولّدة:
  لا تعدّل مخرجاتها يدويًا، بل أعد البناء.
- **`editions/`** تحوي الدفعات المسلّمة فقط. اللقطات والمخرجات التجريبية تذهب إلى
  `build/` المستثنى من Git.
- **الخطوط** مشتركة ولا تُنسخ داخل مشروع كتاب؛ تجاوز `print.css` مسموح عند الحاجة فقط.
- **المسارات داخل `manifest.json`** نسبية إلى مجلد المشروع، عدا `source.dir` فهو نسبي
  إلى جذر المستودع.

## إضافة كتاب جديد

```sh
python scripts/new_book.py add-source --file ~/book.pdf --slug some-book-1st-en \
    --title "Some Book" --author "A. Author" --publisher "Publisher" \
    --edition 1 --year 2020 --language en --rights-status unresolved

python scripts/new_book.py add-book --slug some-book-ar --source some-book-1st-en \
    --title-ar "بعض الكتاب" --author-ar "المؤلف"
```

الأداة تحسب البصمة وعدد الصفحات، وتنشئ الهيكل، وتربط الأصل بالمشروع. تترك **خريطة
الطريق فارغة عمدًا**: عناوين الفصول ونطاقات صفحاتها تُقرأ من الأصل وتُثبَّت يدويًا،
ولا تُخمَّن أبدًا.

`tests/test_repository_layout.py` يفرض هذه البنية على كل الكتب الموجودة، فأي مشروع
يُضاف بشكل مختلف سيفشل الفحص بدل أن يمر بصمت.
