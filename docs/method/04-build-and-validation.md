# 04 — البناء والفحص

البناء **محلي وغير متصل** بعد تثبيت الاعتماديات: لا تُرسل النصوص إلى خدمة ترجمة ولا
إلى الإنترنت، والخطوط تُضمَّن كـ data URLs، والمُصيّر يحجب طلبات الشبكة. حافظ على هذه
الخاصية.

## المتطلبات

Python 3.10+ (اختُبر على 3.11) وNode.js 22.17+ (اختُبر على 22) على Linux x86-64.
الاعتماديات مثبّتة الإصدارات في `requirements.txt` و`package-lock.json`؛ لا ترفعها
ارتجالًا.

```sh
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
npm ci
```

استخدم مسار `.venv/bin/python` صراحةً؛ تفعيل البيئة في أمر سابق ليس افتراضًا موثوقًا
عبر الأوامر أو الجلسات.

## الأوامر

كل الأوامر من جذر المستودع، وتعمل على **كتاب واحد** عبر `--book <slug>`:

```sh
# 1) تحقق من المصادر والروابط وبصمة الأصل — لا يكتب مخرجات
.venv/bin/python scripts/build_book.py --book <slug> --check --verify-source

# 2) الاختبارات (تبني في مجلد مؤقت وتقارن بالمخرجات المنشورة)
.venv/bin/python -m unittest discover -s tests -v

# 3) معاينة دون المساس بالدفعات المسلّمة
.venv/bin/python scripts/build_book.py --book <slug> --output-dir build/preview

# 4) بناء الدفعة الفعلية إلى books/<slug>/editions/
.venv/bin/python scripts/build_book.py --book <slug>
```

`scripts/build_book.py --list` يسرد مشاريع الكتب المتاحة. وعند وجود كتاب واحد فقط
يمكن حذف `--book`.

## ماذا يفحص `--check`؟

- تطابق عناوين الوثائق مع البيان، ووجود محتوى عربي جوهري (لا عناوين فارغة).
- تطابق كل فصل مُعدّ مع سجل تغطيته: الأقسام وترتيبها وعناوينها، الأشكال، الجداول،
  والمختبرات.
- سلامة كتل الشيفرة: لغات معروفة (`sh`/`text`)، ASCII فقط، بلا محارف تحكم اتجاهية،
  وبلا أسوار غير مغلقة.
- روابط Markdown المتقاطعة، وتفرّد معرّفات HTML، و`dir="ltr"` على عناصر الشيفرة.
- ثبات النسخ المؤرشفة، ومنع استخدام اسم دفعة مؤرشفة للدفعة الجارية.
- أن الفصول المرقّمة متسلسلة، وأن كل فصل `draft` له وثيقة حقيقية، وكل `pending` بلا
  وثيقة منتحلة.

`--verify-source` يضيف: مطابقة `source.json` مع البيان، ومطابقة بصمة الأصل وعدد صفحاته.

## الاختبارات

`tests/test_repository_layout.py` عام لكل الكتب: يفرض البنية القانونية وسلامة سجلات
الأصول وعدم تكرار الخطوط. بقية الاختبارات بأسماء مسبوقة بـ slug الكتاب.

- اختبارات البناء تبني PDF كاملًا في مجلد مؤقت وتقارنه بالملف المنشور (عدد الصفحات،
  الفهرس، والنص المستخرج).
- لا تُنفَّذ كتل الأوامر الموجودة في الكتاب تلقائيًا. توجد قائمتان مسموحتان ببصمات
  مراجعة: أمثلة آمنة للقراءة فقط، ومختبرات الفصل المعني. البصمات تُقارن **قبل**
  التنفيذ، ويجري التنفيذ في أدلة مؤقتة ومجموعات عمليات معزولة.
- إضافة مثال جديد = مراجعة بشرية لأمره وأثره ومخرجاته المتوقعة، ثم إضافة بصمته.
  لا تُعِد توليد البصمات لتجاوز فشل.

## المنصات الأخرى

حزمة Chromium المرفقة تستهدف Linux x86-64. على منصة أو معمارية أخرى، أو لاستخدام
متصفح مثبّت مسبقًا:

```sh
BOOK_CHROMIUM_PATH="/path/to/chromium" python scripts/build_book.py --book <slug>
```

## قواعد المخرجات

- `editions/` يُولَّد بالبناء فقط. **لا تعدّل PDF أو Markdown المجمّع يدويًا.**
- المخرجات التجريبية واللقطات تذهب إلى `build/` أو مجلد مؤقت مستثنى من Git.
- الدفعات السابقة المسجّلة في `archived_editions` لا يُعاد بناؤها من مصادر متغيرة؛
  بصماتها مثبتة والبناء يفشل إن تغيّرت.
- بعد آخر تغيير في التنسيق، حدّث عدد الصفحات والبصمة في `AGENTS.md` — لا تعتمد معاينة
  سابقة للتحديث النهائي.
